구현 옵션 선택

Windows 관리자 서비스 writer 전환 (design-windows-service-writer.html) 구현을 시작하기 전에, 당신이 정해줘야 하는 3가지 결정입니다. 카드를 클릭해 고른 뒤 하단의 결정 요약 복사를 눌러 그대로 붙여넣어 주세요.

먼저, 상황 요약

무엇을 만드나

설치형 LocalSystem 관리자 서비스가 index.db 쓰기를 전담하고, GUI·MCP는 read-only가 되는 구조로 전환합니다. writer 교대가 사라져 dual-writer 버그 부류가 소멸합니다.

설계 검증 완료

문서의 선행 결함 S1–S7이 현재 코드(mft_indexer.rs·usn_watcher.rs)에 실제로 존재함을 확인했습니다. 설계는 정확합니다(라인 번호만 드리프트, main.rs는 현재 8,169줄).

핵심 제약 — 이 세션은 관리자 권한 아님

서비스 등록/기동, NSIS 설치, SCM·ACL·named pipe·USN 동작을 내가 직접 끝까지 검증할 수 없습니다. 코드 작성·컴파일(Windows MSVC)·단위테스트·프런트 빌드는 가능합니다. → 아래 결정 ②의 배경.

기존 미커밋 작업(WIP)

트리에 다른 기능(nonadmin-indexing-perf)의 미커밋 변경 약 1,240줄이 있습니다. 그 위에 얹어 작업하고, 그 기능은 건드리지 않으며, 커밋 시 내 파일만 스테이징합니다.

구현 단계(Phase) 한눈에

범위(결정 ①)를 이해하려면 각 Phase가 무엇을 포함하는지 알아야 합니다. 릴리스 규칙: Phase 0–3은 반드시 한 릴리스로 함께 배포해야 합니다(중간 배포 시 서비스+GUI 동시 writer 부활). Phase 4만 후속 릴리스가 가능합니다.

①범위 — 어디까지 구현할까

Phase 0–3 (단일 릴리스) 추천

설계가 요구하는 완전한 배포 단위. 서비스·인스톨러·read-only 전환까지 전부 포함하며, 이대로 출시 가능합니다.

  • Phase 4는 설계 스스로 후속으로 미룸 — 지금 안 해도 됨
  • 가장 명확한 "완성" 지점

Phase 0–4 (후속 옵션 포함)

위 전부 + Phase 4 후속 옵션(관리자 잠금·프로필 제외·lib 분리·다중 볼륨)까지 지금 구현.

  • 범위가 크게 늘어남 (특히 lib 분리는 대규모 리팩터링)
  • 설계상 나중에 해도 안전한 항목들

②"완료"의 기준 — 검증을 어디까지

이 세션은 관리자 권한이 아니라서, 서비스·인스톨러·SCM·ACL·파이프 경로를 내가 직접 끝까지 돌려볼 수 없습니다. 그래서 "완료"의 의미를 정해야 합니다.

코드 + 컴파일 + 단위테스트 + 런북 추천

내가 헤드리스로 할 수 있는 최대치. 모든 코드를 작성하고 컴파일(Windows)·단위테스트를 통과시킨 뒤, 승격 수동 테스트 런북을 넘겨드립니다.

  • 단위테스트: S1–S7 분류, 파이프 파서, 큐 코얼레싱, 경로/config 검증, migrate 멱등, default_db_path
  • 런북: §7 시나리오 ①–㉙ (당신이 직접 실행)

위 + 라이브 검증 (당신이 승격 단계 실행)

위와 동일 + 승격이 필요한 순간 당신이 대신 실행(예: ! sc create ..., 실제 설치)하고 결과를 알려주면, 서비스·인스톨러 동작을 함께 라이브로 검증합니다.

  • 실동작까지 확인 — 가장 확실함
  • 당신의 손이 중간중간 필요 (elevated 명령 실행·설치)

③전달·리뷰 방식 — 큰 변경을 어떻게 볼까

단계별 리뷰·커밋 추천

각 Phase(0→1→2→3)를 끝낼 때마다 멈춰서 diff + 테스트 결과를 보여드리고, 승인 시에만 커밋합니다(당신의 커밋 정책 준수).

  • 작은 리뷰 단위 — 방향을 조기에 교정
  • Phase 0부터 바로 시작 (모든 범위 옵션에 공통)

연속 구현 후 최종 일괄 리뷰

4개 Phase를 연속으로 구현한 뒤 한 번에 리뷰합니다.

  • 전체 그림을 빨리 봄
  • diff가 매우 커지고, 방향 교정이 늦어질 수 있음

※ 어떤 범위를 고르든 Phase 0(S1–S7)이 공통 시작점이라, 결정 후 바로 착수할 수 있습니다.
